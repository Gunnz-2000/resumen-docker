PRIMER CONTENEDOR-------------------------------------------------------

---- docker run hello-world
docker:indica que estamos usando docker
run: que estamos corriendo una imagen
Los contenedores nacen de las imágenes.
si no tenemos la imagen la descarga.

---- docker ps
mostrar todos los contenedores

---- docker ps -a
mostrar todos los contenedores incluso si están apagados

---- docker images
listar todas las imágenes

---- docker search nginx
listar todas las imágenes nginx de docker hub(hay una oficial)

---- docker pull nginx
descargar la imagen nginx de docker hub

---- docker rm id_contenedor
eliminar un contenedor

---- docker rmi nombre_imagen(talvez id también)
eliminar una imagen
Nota:No puedes eliminar una imagen que le pertenece a un contenedor(primero elimina el contenedor)

TRABAJAR EN EL SUBSISTEMA DE WINDOWS PARA LINUX(WSL)-------------------------------------------------------

---- wsl
entrar al subsistema
exit -> para salir

---- docker run --name contenedor1 hello world
pasarle algo(nombre al contenedor en este caso-no puedes tener 2 contenedores con el mismo nombre)

---- docker inspect nombre_contenedor
ver toda la información del contenedor

---- docker container prune
eliminar todos los contenedores

---- docker run -it ubuntu
ejecutar la imagen ubuntu en un modo interactivo - si no existe la imagen la descarga
	Se abre la terminal para interactuar con la imagen - se puede ejecutar cualquier comando de linux
	exit -> para salir

---- docker run --name alwaysup -d ubuntu tail -f /dev/null
crea un contenedor de la imagen ubuntu -d para se ejecute en segundo plano(no se bloquee al cerrar) y
 -f /dev/null para que arranque activo

---- docker run -it --rm -d -p 8080:80 --name web nginx:latest
-p para los puertos; el primero de la máquina y el segundo del contenedor
-rm para que ni bien detengas el contenedor; se elimine
gracias a los puertos te puedes comunicar con contendeor sin tener que tener instalado en tu computadora

---- docker stop nombre_o_id_contenedor
para detener un contenedor

DOCKER FILE-------------------------------------------------------
Archivo de texto que contiene instrucciones que docker usa mediante build para construir una imagen. y Al ejeuctar
la imagen con run se tiene docker container.

---- docker run [opciones] IMAGEN [COMANDO] [ARGS...]
sintaxis de docker

---- cd desktop
para acceder a mi escritorio

---- mkdir curso-docker
crear la carpeta con ese nombre

---- touch DockerFile
crear archivo con ese nombre

---- docker build -t ubuntu-new .
construir la imagen a través del archivo dockerfile, el . indica donde se encuentra est archivo(en este caso directorio actual)
y -t para ponerle nombre en este caso ubuntu-new

---- docker run -it -p 7070:70 ubuntu-new /bin/bash
/bin/bash -> obtener una terminal interactiva con bash

---- ls
para ver archivos dentro

---- cat hola.txt
para mostrar contenido

---- docker run -it -p 7080:80 ubuntu-new
no sobreescribe en cmd del dockerfile

---- docker exec -it my-container ls /usr/share/nginx/html
docker exec entra a un contenedor que ya est+a corriendo.
ls -> lista archivs
/usr/share/nginx/html -> ruta a listar
verificar que archivos estén donde deben estar

---- cp Dockerfile ejemplo1
copia el archivo Dockerfile

remover archivo dockerfile

---- docker run my-image1 "mensaje extra" más recomendado es: ---- docker run my-image1 echo "mensaje extra"
para añadir mensaje si es que es un entrypoint,para sobreescribir si es un cmd

REDES EN DOCKER-------------------------------------------------------
comunicacion entre contenedores y el mundo exterior
Puedes crear tus propias redes personalizadas

---- docker network ls
lista todas las redes de Docker(bridge-predeterminada)

---- docker network create my-network
crear mi red con ese nombre

---- docker network inspect my-network
inspeccionar red con ese nombre

---- docker run -d --name my-container-5 --network my-network nginx:latest
crea y arranca un contenedor llamado my-container-5, conectado a la red my-network, usando la imagen nginx:latest

---- docker network disconnect my-network my-container-6
desconecta el contenedor my-container-6 de la red my-network

---- docker network rm my-network
eliminar la red my-network

PERSISTENCIA Y GESTIÓN DE DATOS  EN DOCKER-------------------------------------------------------
si eliminas el contenedor todo lo que había dentro se pierde.
Por eso existen mecanismos para persistir datos fuera del ciclo de vida del contenedor.
volumenes:Un espacio de almacenamiento gestionado por Docker, que vive fuera del contenedor pero dentro del área de Docker.
bind mounts:Montas una carpeta o archivo de tu propia máquina (host) directamente dentro del contenedor. Tiene datos expuestos
por eso solo para pruebas.

---- docker run -d --name my-mongodb-container -v "/mongodb_data:/data/db" mongo:latest
Esto es un bind mount. Formato: -v <ruta_en_el_host>:<ruta_en_el_contenedor>
crea y arranca un contenedor MongoDB en segundo plano, llamado my-mongodb-container, 
y persiste sus datos en la carpeta /mongodb_data de tu máquina host.

---- docker exec -it my-mongodb-container bash
abre una terminal bash interactiva dentro del contenedor que ya está corriendo

---- mongosh
para interactuar con la consola de mongo

---- docker run --name mysql-container -v "/mysql_db:/var/lib/mysql" -e MYSQL_ROOT_PASSWORD=1234 -d mysql
crea y arranca un contenedor MySQL en segundo plano, llamado mysql-container,
con persistencia de datos en /mysql_db y contraseña de root 1234

---- docker exec -it mysql-container bash
abre una terminal bash interactiva dentro del contenedor que ya está corriendo

---- mysql -u root -p
consola de mysql

---- docker volume ls
listar volúmenes y bind mounts

---- docker volume create db_mongo
crear volumen

---- docker run -d --name mongocontainer --mount src=db_mongo,dst=/data/db mongo
crea y arranca un contenedor MongoDB en segundo plano, llamado mongocontainer, usando 
un volumen gestionado por Docker llamado db_mongo montado en /data/db

DOCKER COMPOSE-------------------------------------------------------
herramienta para crear multiples contenedors con archivo .yml 
y aqui colocas todos los servicios que necesites

---- docker compose up -d
levanta todos los servicios definidos en tu archivo docker-compose.yml
creándolos y arrancándolos en segundo plano.

---- docker compose down
detiene y elimina todos los contenedores y redes que docker compose up había creado para tu proyecto.

---- docker compose stop db
detiene el servicio db definido en tu docker-compose.yml, 
sin eliminarlo ni tocar los demás servicios.

---- docker compose rm db
elimina el contenedor del servicio db

MULTI-STAGE BUILDS EN DOCKER(multicapas)-------------------------------------------------------
Cuando construyes una imagen Docker, normalmente necesitas herramientas de compilación 
(compiladores, SDKs, dependencias de desarrollo) para generar el artefacto final. 
Pero esas herramientas no las necesitas en producción.
Divides el Dockerfile en varias etapas (FROM ... AS nombre). Cada etapa es independiente 
y puedes copiar solo lo necesario de una etapa a otra.
Etapa de build: usa una imagen pesada con todas las herramientas, compila el proyecto.
Etapa final: usa una imagen ligera (Alpine, distroless, scratch) y copia solo el artefacto de la etapa anterior.
Las etapas intermedias se descartan al final. La imagen resultante contiene solo lo que copiaste.
